
# 자바의 특징

## 표준 스펙과 구현

자바는 **스펙** 와 **구현** 으로 나뉜다.

스펙은 일종의 설계도이고, 구현은 이 설계도를 보고 OpenJDK, Amazon Corretto, Eclipse Temurin 등 실제로 사용할 수 있게 만든 자바 프로그램이다.

## 변경의 용이

![자바 표준 스펙과 구현 구조 이미지](../assets/Pasted%20image%2020261015154710.png)

모든 자바 구현체는 동일한 표준 스펙을 따른다. 따라서 원래 OpenJDK를 사용하다가 중간에 Amazon Corretto로 자바 프로그램을 바꿔도 대부분 문제없이 작동한다는 장점이 있다.

표준 스펙에서는 크게 자바 컴파일러, 실행 라이브러리, 자바 가상 머신에 대한 스펙을 정의하고 있고, 구현체는 이것들을 구현하고 있다.

> 자바를 공부하다보면 인터페이스(위에서 설명한 자바의 스펙처럼 설계도와 비슷한 역할을 함)와 이를 구현한 구현체의 개념이 자주 등장하며, 실제로 사용할 때도 변경의 용이성이라는 장점을 그대로 가져갈 수 있다. 자바라는 플랫폼 자체의 특징이 이를 반영하고 있는 것을 알 수 있는 재미있는 부분인 것 같다.

## 운영체제 독립성

일반적인 프로그램은 다른 OS에서 실행할 수 없다. 각 OS별로 명령어가 다르기 때문이다. 자바 프로그램은 자바(JVM)가 설치된 모든 OS에서 동일하게 실행할 수 있다. 이것이 가능한 이유는 마찬가지로 모든 자바 구현체는 표준 스펙을 따르기 때문이다. 윈도우 자바는 윈도우 명령어에 맞춰져 있고, 리눅스 자바는 리눅스 명령어에 맞춰져 있다.

각 OS에 맞게 자바를 설치하기만 하면 동일한 자바 코드(바이트 코드)를 가지고도 동일하게 실행할 수 있다.

> 동일한 소스 코드, 동일한 바이트코드, 다른 것은 JVM뿐

## 개발과 배포 편의성

OS에 구애 받지 않고 실행할 수 있다는 것은 개발 환경과 배포 환경이 달라도 괜찮다는 의미도 있다. 배포할 서버는 리눅스 서버여도, 개발할 때는 편의를 위해 윈도우나 맥에서 개발해도 프로그램은 동일하게 작동한다.

## 컴파일과 실행 단계

![](../assets/Pasted%20image%2020261015154808.png)

1. 자바 코드 작성
2. 컴파일
    - `javac`라는 컴파일러를 사용 (`javac Hello.java`)
    - 자바 코드가 바이트코드(`.class`)로 변환
    - 이 과정에서 문법 오류와 최적화도 진행
3. 실행
    - `java` 프로그램을 사용해서 실행 (`java Hello`)
    - JVM이 실행되고 이 위에서 `.class` 파일이 돌아가면서 프로그램이 작동
