
## 제네릭이 필요한 이유

만약 각 타입에 맞춰서 동작해야 하는 클래스가 필요한 경우 기존에는 크게 두 가지 방법으로 해결했어야 했다.

**1. 타입별로 클래스 만들기**
```java
public class IntegerBox {
    private Integer value;
    public void set(Integer value) { this.value = value; }
    public Integer get() { return value; }
}

public class StringBox {
    private String value;
    public void set(String value) { this.value = value; }
    public String get() { return value; }
}
```

- 필요한 타입이 늘어날 때마다 클래스를 계속 만들어야 돼서 코드 재사용이 힘들다.

**2. Object 클래스를 사용해 다형성을 활용**
```java
public class ObjectBox {
    private Object value;
    public void set(Object object) { this.value = object; }
    public Object get() { return value; }
}
```

- 잘못된 타입의 값을 넣으면 컴파일 단계에서 확인하지 못 하고 런타임 에러로 발견됨
- `get()`으로 값을 받아올 때마다 위험한 다운캐스팅이 필요함

제네렉을 사용하면 **코드 재사용**과 **타입 안정성**이라는 두 마리 토끼를 모두 잡은채로 해결이 가능하다.

## 제네릭 사용법

```java
public class GenericBox<T> {
    private T value;
    public T get() { return value; }
    public void set(T value) { this.value = value; }
}
```

- 클래스 이름 오른쪽에 `<T>`처럼 `<>` 기호 안에 **타입 매개변수**를 넣어서 사용할 수 있다.
- 이렇게 선언하면 해당 클래스는 **제네릭 클래스**가 된다.
- 타입 매개변수는 **클래스 생성 시점에** 타입을 결정한다.
- 타입 매개변수는 여러개를 지정할 수도 있다.

```java
GenericBox<Integer> integerBox = new GenericBox<Integer>();
```

`new GenericBox<Integer>`의 형태로 사용하면

```java
public class GenericBox<Integer> {
    private Integer value;
    public void set(Integer value) { ... }
    public Integer get() { ... }
}
```

컴파일러는 이렇게 `T` 부분이 지정한 타입으로 바뀐 **것처럼** 취급하게 된다. (실제로 `GenericBox<Integer>` 코드를 만들어내는게 아님)

```java
GenericBox<Integer> box1 = new GenericBox<Integer>(); // 타입 직접 입력
GenericBox<Integer> box2 = new GenericBox<>();        // 타입 추론
```

또한 타입 추론으로 생성 부분의 타입은 생략이 가능하다.

## 제네릭의 핵심

제네릭의 가장 중요한 핵심은 "결정을 나중으로 미루는 것"이다. 마치 함수의 매개변수는 실행 시점에 인자를 통해 결정되는 것처럼 말이다.

제네릭(Generic)이라는 단어는 "일반적인", "범용적인" 이라는 뜻을 가지고 있다. 타입을 실행 시점에 결정할 수 있는 덕분에 보다 범용적인, 즉 이를 활용해 **코드 재사용성**을 크게 높일 수 있게 된다.

## 타입 인자 기본형 사용 불가능

제네릭의 타입 인자로는 `int`, `double` 같은 기본형 타입은 사용할 수 없다. 대신 Wrapper Class(`Integer`, `Double`)를 사용한다.

> 타입 소거(type erasure) 때문, 자바의 제네릭은 컴파일 시에만 타입을 검사하고, 바이트코드에서는 타입 매개변수를 `Object`로 바꿈, 기본형은 `Object`의 하위 타입이 아니기 때문에 구조적으로 불가능함

## 타입 인자로 아무것도 넣지 않으면

```java
GenericBox integerBox = new GenericBox();
integerBox.set(10);
Integer result = (Integer) integerBox.get();
System.out.println("result = " + result);
```

만약 제네릭 타입을 사용할 때 `<>`을 지정하지 않고 사용하면, 이는 raw type이라고 해서 타입 매개변수가 `Object`로 사용되는 것처럼 작동한다.

**마치** `Object`로 사용되는 것처럼 보일 뿐, 실제로 raw type은 제네릭 타입 검사 자체를 끄는 행위이기 때문에 절대 사용해서는 안된다. 의도적으로 `Object`를 사용하고 싶다면 명시적으로 `<Object>`를 넣는 것이 권장된다.
